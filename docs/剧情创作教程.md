# JYXR 剧情创作教程

本文面向第一次使用 JYXR Story DSL 的剧情作者。目标不是让你先学 JSON，而是让你能按“写段落 -> 接入口 -> 做分支 -> 检查 -> 进游戏试玩”的顺序完成一条可玩的剧情。

示例均以 `jyxr-expansion` 为目标 MOD。游戏实际读取 `.story.json`，但创作时只编辑 `.story`；保存后编辑器会自动编译并同步两份文件。

## 一、先理解四个概念

### 1. 剧情文件

一条剧情通常写在：

```text
mods/jyxr-expansion/data/story/故事名.story
```

例如：

```text
mods/jyxr-expansion/data/story/baima.story
```

不要手动同时修改同名 `.story.json`。只要存在 `.story`，它就是唯一可写源。

### 2. 剧情段

每个顶格的 `#` 标题都是一个可执行剧情段：

```text
# 白马啸西风_初次见面
李文秀：你是从中原来的？
主角：正是。
```

段名就是剧情 ID，必须全 MOD 唯一。地图事件、世界触发器、`jump`、`call` 和限时任务都会引用这个名字。

建议统一使用：

```text
故事名_阶段_结果
```

例如：

```text
白马啸西风_高昌入口
白马啸西风_高昌战后
白马啸西风_结局_封存石门
```

### 3. 入口

写好剧情段并不代表游戏会自动播放。至少要有一个入口指向它：

- 地图点位的剧情事件；
- 大地图地点的剧情事件；
- `world-triggers.json` 中的世界触发器；
- `game-config.json` 的开局剧情；
- 另一段剧情中的 `jump`、`call` 或限时跳转。

最常用做法是在编辑器的“地图与事件”里新增“进入剧情”事件，并把目标剧情选择为入口段。

### 4. 状态

剧情分支通常读取四类状态：

- 当前状态：队友、物品、银两、道德、时辰、周目等；
- 剧情旗标：由 `set_flag` 写入的自定义布尔值；
- 剧情完成记录：某个剧情段是否已经完整执行结束；
- 地图事件完成记录：某个具体地图事件是否已完成。

剧情旗标、剧情完成记录和限时 key 都会进入存档。

## 二、推荐的完整创作流程

### 第一步：写剧情设计表

动笔前先列五项，不必写长篇策划：

```text
入口：在哪里、什么条件触发
目标：玩家在这段剧情中要解决什么
选择：哪些选择会真正改变后续
资源：需要哪些角色、地图、战斗、物品、音乐、背景
出口：结束后去哪里、解锁什么、是否可重复
```

先把主干写通，再加支线。推荐先控制在 5 到 15 个剧情段，避免一开始出现几十个孤立节点。

### 第二步：准备引用内容

剧情引用的 ID 必须已经存在：

- 说话角色：`characters.json`；
- 战斗：`battles.json`；
- 奖励物品：`items.json`；
- 地图：`maps.json`；
- 商店：`shops.json`；
- 音乐、背景、音效：`resources.json`；
- 称号：`resources.json` 中的 `nick.称号ID`。

编辑器会补全这些 ID，也会在引用不存在时标红。不要为了“先保存”随便拼一个 ID。

### 第三步：创建 `.story`

在“剧情与任务”工作区新建剧情源，例如：

```text
book-example.story
```

先写一个能结束的最小入口：

```text
# 示例故事_入口
旁白：这是故事的开头。
主角：先把主线跑通，再继续扩写。
log 开始调查示例故事。
```

### 第四步：接地图入口

进入“地图与事件”：

1. 选择地图和点位。
2. 添加“进入剧情”事件。
3. 目标选择 `示例故事_入口`。
4. 设置概率和重复方式。
5. 添加需要的触发条件。
6. 保存地图。

常见入口条件：

```text
队友在队：key_in_team 郭靖
队友不在队：key_not_in_team 郭靖
前置剧情完成：should_finish 示例故事_前置
前置剧情未完成：should_not_finish 示例故事_入口
持有物品：have_item 示例令牌 1
指定时辰：time_slot 子 丑 寅
```

地图事件中的多个条件是“全部满足”才触发。

### 第五步：写分支和收束

让选择改变信息、关系、战斗或后续入口，而不只是换一句对白。分支最终可以重新汇合：

```text
# 示例故事_入口
主角：要先调查哪里？
- 去客栈
  jump 示例故事_调查客栈
- 去码头
  jump 示例故事_调查码头

# 示例故事_调查客栈
掌柜：你在客栈找到了一封信。
jump 示例故事_汇合

# 示例故事_调查码头
船夫：你在码头看见了可疑船只。
jump 示例故事_汇合

# 示例故事_汇合
if should_finish 示例故事_调查客栈
  主角：先查这封信。
else
  主角：先查那艘可疑船只。
```

### 第六步：用流程图检查

切换到“流程”视图，至少检查：

- 入口段是否有外部入口；
- 每个 `jump` / `call` 是否指向正确段落；
- 有没有孤立段落；
- 有没有意外死路；
- 分支是否能到达预期结局；
- 是否出现重复剧情 ID。

### 第七步：保存并运行“检查”

点击保存会同时：

1. 编译 `.story`；
2. 生成同名 `.story.json`；
3. 校验命令和参数；
4. 校验角色、物品、地图、战斗等引用；
5. 创建时间戳备份。

右上角“检查”应达到 0 错误。警告也应逐条确认，不要默认忽略。

### 第八步：进游戏试玩

至少准备三类存档：

- 从未触发过的新存档；
- 关键队友在队的存档；
- 关键队友不在队的存档。

每条主要选择和战斗胜负都要实际走一次。编辑器检查能发现结构问题，但不能代替节奏、对白和难度试玩。

## 三、DSL 基础写法

### 对白与旁白

```text
李文秀：这里风大，别离队伍太远。
主角：我会小心。
旁白：远处传来急促的马蹄声。
```

说话人使用 `角色名：文本`。建议让说话人能在 `characters.json` 中按 ID 或姓名找到，否则可能没有头像。

文本含有空格没有关系。命令参数含有空格时使用双引号：

```text
log "在高昌入口发现了半张地图"
```

### 注释

```text
// 这里只解释创作意图，不会进入游戏
```

### 缩进

- 顶层语句不缩进。
- 每深入一级固定使用 2 个空格。
- 不使用 Tab。

错误示例：

```text
if key_in_team 郭靖
   郭靖：这里用了 3 个空格，会报错。
```

### 跳转 `jump`

`jump` 进入另一段，并且不会返回：

```text
jump 示例故事_战后
```

`jump` 后面的同级语句永远不会执行，编辑器会报不可达错误。

### 调用 `call` 与返回 `return`

`call` 适合复用公共对白或奖励。被调用段结束或执行 `return` 后，会回到调用点继续：

```text
# 示例故事_胜利
call 示例故事_公共奖励
主角：奖励领完了，继续赶路。

# 示例故事_公共奖励
item 小还丹 2
get_money 100
return
```

不要用 `call` 进入永远不会返回的主线段；这种情况应使用 `jump`。

## 四、选择、条件和队友分支

### 普通选择

提示对白后紧跟选项：

```text
主角：现在怎么办？
- 追上去
  jump 示例故事_追击
- 留在原地
  jump 示例故事_等待
```

选项文本不是命令。选项下方缩进的内容才会执行。

### 判断队友是否在当前队伍

推荐按稳定角色 ID 判断：

```text
if key_in_team 郭靖
  郭靖：这片草原让我想起蒙古。
  jump 示例故事_郭靖路线
else
  主角：若郭靖在这里，也许能认出这些马蹄印。
  jump 示例故事_普通路线
```

四个相关判断：

| 判断 | 含义 |
| --- | --- |
| `key_in_team 角色ID` | 指定 ID 的角色在当前队伍。推荐使用。 |
| `key_not_in_team 角色ID` | 指定 ID 的角色不在当前队伍。 |
| `in_team 角色姓名` | 指定姓名的角色在当前队伍。适合确实按姓名判断。 |
| `not_in_team 角色姓名` | 指定姓名的角色不在当前队伍。 |

这里的“在队”准确说是活跃同行角色，包含当前队伍 `Members` 和随队池 `Followers`：

- `join 郭靖` 后为在队；
- `follow 郭靖` 加入随队池，也会被判断为在队；
- `leave 郭靖` 或 `leave_follow 郭靖` 后进入后备池 `Reserves`，才算不在队。

注意，`friendCount`、角色属性条件和角色技能条件只检查当前队伍 `Members`，不计算 `Followers`。需要判断某个剧情人物是否随行时用 `key_in_team`；需要判断当前正式编队人数时才用 `friendCount`。

如果角色允许改名，按 ID 的 `key_in_team` 比按姓名的 `in_team` 更可靠。

### 根据队友显示不同选项

`when` 只控制一组选项是否出现：

```text
主角：谁来辨认掌印？
- 自己查看
  jump 示例故事_自行调查
when key_in_team 郭靖
  - 请郭靖查看
    郭靖：这是蒙古摔跤留下的手印。
    jump 示例故事_郭靖线索
```

至少保留一个无条件选项，否则条件不满足时玩家可能无选项可选。

### 多个条件组合

支持 `and`、`or`、`not` 和括号：

```text
if key_in_team 郭靖 and have_item 蒙古腰牌 1
  郭靖：有这块腰牌，他们会让我们进营地。
elif key_in_team 郭靖 or should_finish 示例故事_结识守卫
  主角：至少有人能替我们说明来意。
else
  主角：只能另找入口了。
```

复杂条件建议加括号明确意图：

```text
if (key_in_team 郭靖 or key_in_team 黄蓉) and have_item 高昌地图 1
  jump 示例故事_隐藏入口
```

### 判断银两和内置变量

可以使用谓词：

```text
if have_money 500
  cost_money 500
  掌柜：房钱收下了。
else
  掌柜：银两不够。
```

也可以比较内置变量：

```text
if $money >= 500 and $daode >= 20
  掌柜：既有钱，名声也不错，请进。
```

可直接读取的变量：

| 变量 | 含义 |
| --- | --- |
| `$money` / `$silver` | 当前银两 |
| `$yuanbao` / `$gold` | 全局元宝 |
| `$round` | 当前周目 |
| `$game_mode` | `normal`、`hard` 或 `crazy` |
| `$menpai` | 当前门派 ID |
| `$daode` | 道德 |
| `$haogan` | 默认关系目标的好感 |
| `$rank` | 江湖排名 |
| `$zhenlong_level` | 珍珑棋局显示层级 |
| `$last_trial_count` | 最近一次试炼计数 |

## 五、旗标、完成记录和事件记录

### 旗标 `set_flag`

旗标用于记录“玩家做过什么选择”：

```text
set_flag 示例_放走刺客
```

之后按变量判断：

```text
# 示例故事_放走刺客路线
set_flag 示例_放走刺客
jump 示例故事_刺客报恩

# 示例故事_刺客报恩
if $示例_放走刺客 == true
  刺客：上次你饶我一命，今日我还你。
else
  刺客：我们没什么可谈。
```

上例中 `示例故事_刺客报恩` 只能从已经执行 `set_flag` 的路线进入，所以变量一定存在。未设置的自定义变量不会自动等于 `false`；直接读取一个不存在的 `$旗标` 会导致运行时错误。

如果同一段可能从其他路线进入，先用确定存在的完成记录做短路保护：

```text
if should_finish 示例故事_放走刺客路线 and $示例_放走刺客 == true
  刺客：上次你饶我一命，今日我还你。
else
  主角：这里没有人接应。
```

`and` 会先判断左侧。没有完成“放走刺客路线”时，右侧旗标不会被读取。

清除旗标：

```text
clear_flag 示例_放走刺客
```

`clear_flag` 会删除变量，不是把它设置为 `false`。清除后不要继续直接读取 `$示例_放走刺客`。

旗标命名建议带故事前缀，避免和其他剧情重名：

```text
白马_尊重部落
白马_封存高昌
书剑_救下霍青桐
```

旗标只表示你明确记录的状态，不会自动代表某段剧情已经完成。

### 剧情完成 `should_finish`

当一个剧情段完整执行结束时，游戏会自动记录它已经完成：

```text
if should_finish 示例故事_找到地图
  主角：地图已经到手，可以出发了。
else
  主角：还要继续寻找地图。
```

反向判断：

```text
if should_not_finish 示例故事_找到地图
  jump 示例故事_寻找地图
```

适用原则：

- “这段剧情是否播过”使用 `should_finish`；
- “玩家在剧情里选了什么”使用 `set_flag`；
- 不要为了判断选择结果，滥用某个中间段是否完成。

### 上一段剧情 `follow_story`

判断刚刚完成的上一段剧情：

```text
if follow_story 示例故事_救人路线
  村民：多谢你刚才出手救人。
```

它只适合紧邻流程，不适合长期状态。长期结果仍应使用旗标。

### 地图事件完成 `event_completed`

地图事件键格式为：

```text
地图ID|点位ID|事件序号
```

例如：

```text
if event_completed 哈萨克部落|李文秀|0
  主角：我们已经见过李姑娘了。
```

剧情完成和地图事件完成不是一回事：同一剧情可能从多个地图事件触发，同一地图事件也可能进入不同后续流程。

## 六、战斗写法

战斗 ID 必须已经存在于 `battles.json`：

```text
battle 示例故事_山贼战
- win
  get_money 200
  log 击退了山路上的盗匪。
  jump 示例故事_战斗胜利
- lose
  jump 示例故事_战斗失败
- timeout
  jump 示例故事_战斗超时
```

结果分支只能写：

- `win`：胜利；
- `lose`：失败；
- `timeout`：超时。

不是所有战斗都必须写 `timeout`，但限时战斗应该写。战斗阵容、地图背景和必选角色在“战斗编排”工作区配置，不在 DSL 中配置。

## 七、常用命令速查

以下命令来自当前游戏正式契约。方括号表示可选参数，不要把方括号本身写进命令。

### 剧情流程

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `jump 段落ID` | 跳转且不返回 | `jump 白马_战后` |
| `call 段落ID` | 调用公共段，结束后返回 | `call 公共_发奖励` |
| `return` | 从 `call` 返回 | `return` |
| `map 地图ID` | 进入地图 | `map 大地图` |
| `shop 商店ID` | 打开商店并等待关闭 | `shop 长安商店` |
| `log 文本` | 写入江湖日志 | `log "发现高昌入口"` |
| `suggest 文本` | 显示剧情提示 | `suggest "前方似有异动"` |

### 状态和时间

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `set_flag 名称` | 设置自定义布尔旗标 | `set_flag 白马_看见伤疤` |
| `clear_flag 名称` | 删除自定义旗标 | `clear_flag 白马_看见伤疤` |
| `cost_day 天数` | 推进日期 | `cost_day 2` |
| `set_time_key key 天数 [超时段落]` | 创建限时任务 | `set_time_key 救人 3 示例_救人失败` |
| `clear_time_key key` | 清除限时任务 | `clear_time_key 救人` |
| `world_trigger on/off` | 开启或阻塞世界触发 | `world_trigger off` |
| `set_round 周目` | 设置周目 | `set_round 2` |
| `set_game_mode 模式` | 设置难度 | `set_game_mode hard` |
| `set_no_regret` | 开启无悔规则 | `set_no_regret` |

`set_time_key` 的天数必须大于 0。超过期限后 key 会被移除；填写了超时段落时，宿主会进入该剧情。

### 队伍

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `join 角色ID` | 加入当前队伍 | `join 李文秀` |
| `follow 角色ID` | 加入随队池 | `follow 女主` |
| `leave 角色ID或姓名` | 从当前队伍移入后备池 | `leave 李文秀` |
| `leave_follow 角色ID或姓名` | 从随队池移入后备池 | `leave_follow 女主` |
| `leave_all` | 除主角外的当前队伍成员全部移入后备池，不处理随队池 | `leave_all` |
| `random_join [角色ID列表]` | 从列表随机选一人入队 | `random_join [郭靖, 黄蓉]` |

### 物品与货币

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `item 物品ID [数量]` | 获得物品 | `item 小还丹 2` |
| `cost_item 物品ID [数量]` | 扣除物品 | `cost_item 银票 1` |
| `random_item [物品ID列表] [数量]` | 随机获得列表中的一种物品 | `random_item [小还丹, 大还丹] 1` |
| `get_money 数量` | 增加银两 | `get_money 500` |
| `cost_money 数量` | 扣除银两 | `cost_money 500` |
| `yuanbao 数量` | 调整元宝，可用负数扣除 | `yuanbao 10` |

扣除物品或货币前先用条件判断数量，避免运行时失败：

```text
if have_item 银票 2
  cost_item 银票 2
else
  掌柜：你没有足够的银票。
```

### 道德、好感和门派

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `daode 变化值` | 调整道德 | `daode 3` |
| `haogan 变化值` | 调整默认关系目标好感 | `haogan 5` |

## 九、可直接复用的完整示例

下面是一条包含地图入口所需主段、队友分支、旗标、条件选项、战斗、公共奖励和结局的最小完整故事：

```text
# 示例故事_入口
background 地图.塞外
music 音乐.太行八径
旁白：山道旁倒着一辆货车，车辙一直延伸到树林深处。
if key_in_team 郭靖
  郭靖：车夫没有受伤，应该是自己追进树林了。
  call 示例故事_郭靖观察
else
  主角：这里只有凌乱脚印，暂时看不出发生了什么。
主角：要怎么办？
- 立即追踪
  jump 示例故事_树林
- 先检查货车
  call 示例故事_检查货车
  jump 示例故事_树林

# 示例故事_郭靖观察
郭靖：车辙很深，山贼带走的货物一定很重。
return

# 示例故事_检查货车
旁白：你在货车夹层找到一瓶没有被发现的伤药。
item 小还丹 1
return

# 示例故事_树林
旁白：林中山贼正在围攻车夫。
when key_in_team 郭靖
  - 让郭靖正面喝止
    郭靖：放下兵器，不要伤人！
    haogan 郭靖 2
    jump 示例故事_战斗
- 从侧面救人
  set_flag 示例_侧面救人
  jump 示例故事_战斗

# 示例故事_战斗
battle 示例故事_山贼战
- win
  jump 示例故事_战后
- lose
  主角：先撤出树林，再想办法。
  map 示例村庄

# 示例故事_战后
车夫：多谢诸位相救。
if should_finish 示例故事_郭靖观察
  车夫：这位郭大侠观察仔细，山贼确实是冲着货物来的。
elif should_finish 示例故事_检查货车
  车夫：你在货车里找到的药，就当作谢礼吧。
else
  车夫：幸好你们来得及时。
call 示例故事_公共奖励
log 解救了被山贼围攻的车夫。
jump 示例故事_结束

# 示例故事_公共奖励
get_money 200
grant_exp 主角 100
return

# 示例故事_结束
主角：此事已了，该继续赶路了。
map 大地图
```

给它接地图事件时，建议设置：

```text
目标剧情：示例故事_入口
重复方式：once
概率：100
条件：should_not_finish 示例故事_结束
```

同时必须先在“战斗编排”创建 `示例故事_山贼战`，否则保存会提示战斗引用不存在。

## 十、最常见的错误

### 1. 写了剧情但游戏里不触发

检查是否有地图事件或世界触发器指向入口段，并确认当前运行的是 `jyxr-expansion`。

### 2. 判断队友永远不生效

`key_in_team` 会同时检查当前队伍和随队池，但不会检查后备池。若结果不符合预期，先在队伍界面确认角色没有进入后备池，再确认使用的是角色 ID：

```text
if key_in_team 郭靖
```

### 3. 旗标判断报“未声明变量”或运行时找不到变量

先确保同一剧情库里存在对应写入：

```text
set_flag 示例_做过选择
```

还要保证当前执行路线一定经过该写入，然后才能读取：

```text
if $示例_做过选择 == true
```

未设置的旗标不是 `false`。共享入口需要使用剧情完成记录保护：

```text
if should_finish 示例故事_选择路线 and $示例_做过选择 == true
  主角：这条路线已经安全设置过旗标。
```

### 4. 所有选项都有条件

条件都不满足时会没有可选项。至少保留一个无条件选项。

### 5. `jump` 后继续写对白

`jump` 不会返回。要返回原处，请使用 `call` 和 `return`。

### 6. 扣除物品或银两时运行失败

先用 `have_item` 或 `have_money` 判断，再执行 `cost_item` / `cost_money`。

### 7. 同一个剧情 ID 出现在两个文件

运行时不支持剧情段覆盖，同名段落会使整个 MOD 加载失败。扩写旧剧情时，必须从旧文件移除被替换的段落。

### 8. 直接修改 `.story.json`

存在同名 `.story` 时，下一次保存会重新生成 JSON，手工修改会丢失。只编辑 DSL 源。

### 9. 使用未实现命令完成关键流程

不要用 `tower`、`trial`、`arena` 等占位命令承担必须完成的剧情闭环。

### 10. 只测成功路线

还要测试队友不在队、条件不足、战斗失败、重复进入地图和读档后的状态。
