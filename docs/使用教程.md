# JYXR 编辑器使用教程

这是一份给第一次使用编辑器的人看的说明。编辑器只负责编辑 PC 端 JYXR MOD 数据，不是 Godot 场景编辑器，也不会启动游戏。

如果你的目标是编写对白、选择、队友分支、旗标、战斗和地图触发，请继续阅读[《JYXR 剧情创作教程》](剧情创作教程.md)。

## 一、准备文件

使用编辑器前，需要准备两样东西：

1. 编辑器代码。可以在 GitHub 下载 ZIP，或者使用 Git 克隆：

   ```bash
   git clone https://github.com/aqitianxia/jyxr-editor.git
   ```

2. 一份游戏工作区，例如 `jyxr-android`。工作区的目录结构应该类似这样：

   ```text
   jyxr-android/
   ├── assets/
   └── mods/
       └── jyxr-base/
           ├── mod.json
           └── data/
               ├── maps.json
               ├── characters.json
               └── ...
   ```

注意：打开编辑器时选择的是 `jyxr-android` 这一层，也就是同时包含 `assets` 和 `mods` 的目录。
不要选择 `mods/jyxr-base` 或 `mods/jyxr-base/data`。

## 二、安装运行环境

编辑器需要 `.NET 10 SDK`。在终端执行：

```bash
dotnet --version
```

如果能显示 `10.x.x`，就可以继续。如果提示找不到 `dotnet`，请先安装 .NET 10 SDK，再重新打开终端。

## 三、启动编辑器

打开终端，进入编辑器目录：

```bash
cd /你的路径/jyxr-editor
```

启动编辑器：

```bash
dotnet run --project src/Jyxr.ModEditor/Jyxr.ModEditor.csproj
```

看到下面这类提示，就代表启动成功：

```text
Now listening on: http://localhost:5127
```

然后打开浏览器，访问：

[http://localhost:5127](http://localhost:5127)

端口固定使用 `5127`。不要同时启动两个编辑器实例。

### 直接指定游戏目录

如果不想每次在页面里选择目录，可以启动时直接指定：

```bash
dotnet run --project src/Jyxr.ModEditor/Jyxr.ModEditor.csproj -- --workspace "/你的路径/jyxr-android"
```

路径中有空格时，必须用引号包起来。

## 四、第一次打开工作区

1. 在浏览器打开编辑器。
2. 点击“打开工作区”或“选择工作区”。
3. 选择包含 `assets` 和 `mods` 的游戏根目录。
4. 等待编辑器扫描文件。
5. 在顶部的 MOD 选择框中选择要编辑的 MOD，通常是 `jyxr-base`。
6. 编辑器会显示角色、地图、物品、剧情、武学、资源等工作区。

如果看到“工作区无效”，通常是选错目录。向上返回，选择同时包含 `assets/` 和 `mods/` 的那一层。

## 五、编辑和保存

编辑器的保存规则非常重要：

- 打开文件、查看地图、切换地图、搜索内容，不会修改文件。
- 只有修改输入框、添加、删除、排序或应用高级 JSON 后，才会出现“未保存”。
- 顶部显示的文件名和地图/点位，就是当前未保存修改的位置。
- 点击“保存”后，编辑器才会写入游戏目录。
- 保存时会自动校验 JSON 和游戏内容契约。
- 保存前的旧文件会备份到对应 MOD 下的 `.jyxr-editor/backups/`。

切换页面时如果有未保存修改，编辑器会询问是否放弃。选择“取消”会留在当前页面；选择“确定”才会丢弃内存中的修改。编辑器不会自动帮你保存，也不会偷偷补字段。

## 六、地图编辑特别说明

地图事件使用游戏真实的事件键：

```text
地图ID|点位ID|事件序号
```

事件序号从 `0` 开始。编辑器不会给游戏事件自动生成另一套 ID，也没有“触发模拟”功能。地图工作区只负责查看和编辑真实数据。

## 七、战斗编排特别说明

战斗编排工作区直接编辑当前 MOD 的 `battles.json`。战场固定为 11 列 × 4 行，坐标从 `(0, 0)` 开始；可以拖动单位，或先选择单位再点击目标格，目标格已有单位时会交换位置。

四类部署单位对应的游戏数据如下：

- 玩家位置：`participants` 中 `team` 为 `1`、`characterId` 为 `null`，并使用从 `0` 连续编号的 `partyIndex`。
- 固定友军：`participants` 中 `team` 为 `1`，并引用一个 `characterId`。
- 固定敌人：`participants` 中 `team` 为 `2`，并引用一个 `characterId`。
- 随机敌人：写入 `randomParticipants`，普通敌人的 `tier` 使用 `0` 到 `3`。

战斗背景的 `mapId` 不是 `maps.json` 的地图 ID，而是 `assets/art/battle_bg/` 下图片的文件名，不带扩展名。战斗音乐保存 `resources.json` 中能解析到音频文件的资源 ID。

地图事件选择“进入战斗”后，可以直接搜索 `battles.json` 中的战斗，也可以打开目标战斗或快速创建缺失定义。剧情工作区的可写 DSL / JSON 视图顶部同样提供“插入战斗”：DSL 会插入 `battle` 的 `win`、`lose` 分支，JSON 会向当前剧情段追加对应的运行时步骤。

战斗详情的“引用”页会列出地图、剧情、塔层和世界触发器中的真实战斗调用，并可跳转到调用位置。战斗 ID 必须通过“重命名 ID”修改；确认后编辑器会在一个事务中保存当前 `battles.json` 草稿，并同步更新地图事件、Story DSL、编译后的 Story JSON、塔层和世界触发器。只要正式内容校验失败，所有文件都会恢复原状。

编辑器会检查坐标越界、单位重叠、坏角色引用、玩家序号、背景和音乐资源，以及必选角色是否超过玩家部署位置。这里不会启动或模拟 Godot 战斗，实际胜负流程仍由游戏运行时负责。

## 八、关闭编辑器

编辑完成并保存后，回到运行编辑器的终端，按：

- macOS / Linux：`Ctrl + C`
- Windows：`Ctrl + C`

看到 `Application is shutting down` 后，编辑器就已经关闭。下次使用时重新运行启动命令即可。

## 九、常见问题

### 浏览器打不开 5127

先确认启动编辑器的终端还没有关闭，并且终端中出现了：

```text
Now listening on: http://localhost:5127
```

如果提示端口已经被占用，通常是之前的编辑器还在运行。找到之前启动它的终端并按 `Ctrl + C`，再重新启动。

macOS / Linux 找不到之前的终端时，可以执行：

```bash
lsof -ti:5127 | xargs kill
```

Windows 可以执行：

```bat
netstat -ano | findstr :5127
taskkill /PID 进程号 /F
```

### 保存后游戏没有变化

确认以下几点：

1. 编辑器打开的是正确的游戏根目录。
2. 顶部选择的是正确的 MOD。
3. 已经点击“保存”，而不是只修改后直接关闭浏览器。
4. 游戏读取的正是这个工作区，而不是另一份复制目录。

### 出现校验错误

不要直接忽略错误。点击错误提示查看文件和字段位置，修正后再次保存。保存失败时，编辑器不会用不完整的数据覆盖原文件。
